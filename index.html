Project Overview

Solving Attendance Fraud with
Biometric Intelligence

Traditional manual attendance systems are vulnerable to buddy punching, inaccurate recording, and fraud. This project replaces manual attendance with a real-time, AI-driven biometric verification pipeline — making impersonation virtually impossible.

The Problem

Manual attendance is prone to manipulation (buddy punching), inefficient record-keeping, and lack of audit trails. Existing face recognition systems often use 1:N identification which is slower and less secure for individual-targeted verification scenarios.

The Solution

A 1:1 face verification microservice: the system verifies whether a specific employee's submitted photo matches only their own stored embedding — drastically reducing attack surface and improving speed. Combined with multi-pose registration for robustness.

Verification Workflow

1

Face Registration (Multi-Pose)

Employees register 5 photos: front, left, right, up, down. The endpoint /register validates image quality, checks for duplicate face injection, then stores images to storage/Dataset/. On the 5th image, retrain_model() is triggered synchronously.

2

Embedding Extraction & Model Training

The system scans the entire dataset folder, extracts a 512-dimensional face embedding per image using InsightFace (ArcFace with ResNet50 backbone), and persists the full embedding matrix and name index as pickle files.

3

1:1 Verification at Attendance

When clocking in, Laravel sends the employee's username + live photo to /recognize. The AI filters the embedding database to only that user's rows, computes cosine distance, and accepts if distance < 0.40 (threshold).

4

Attendance Logging

If verification succeeds, Laravel writes the attendance record (employee ID, timestamp, status) to MySQL. The AI service remains stateless and only returns a JSON verdict — clean separation of concerns.

Why 1:1 Verification over 1:N Identification?

Traditional 1:N Identification

Compares face against all employees in the database. As headcount grows, compute time scales linearly. Any face in the database can match — security depends entirely on threshold tuning.

This System: 1:1 Verification

Only compares the incoming face against the claimed user's embeddings (5 vectors). Constant-time regardless of company size. Eliminates cross-person false matches by design — security is architecturally enforced.
